# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Flutter app boilerplate built around a custom `BaseBloc` abstraction, `go_router`,
`rq_network_flutter` (a private Dio-based API client), Firebase (Crashlytics/Analytics),
and a three-flavor build setup (`dev` / `staging` / `prod`). Package name: `flutter_bloc_bp`.

## Commands

Flutter is pinned via FVM (`.fvmrc` → 3.47.2, Dart 3.13.x). Run every Flutter/Dart
command through `fvm` (e.g. `fvm flutter test`) so it uses the pinned SDK.

```bash
flutter pub get

# Run — pass env via --dart-define-from-file. The checked-in .env holds staging values;
# .env.staging and .env.production also exist. There is NO .env.dev despite the README.
flutter run -t lib/main.dart --flavor dev     --dart-define-from-file=.env
flutter run -t lib/main.dart --flavor staging --dart-define-from-file=.env.staging

# Static analysis — strict; uses the flutter/flutter repo's own analysis_options
# (always_specify_types, prefer_relative_imports, prefer_single_quotes, strict-casts...).
flutter analyze

# Tests
flutter test
flutter test test/pages/login_page_test.dart                 # single file
flutter test --plain-name 'Login Page Test Cases'            # single group/test
./test.sh                                                     # coverage + HTML report
```

`./test.sh` needs `jq`, `lcov`, `genhtml` and macOS `open`; it runs tests with coverage,
strips paths listed in `coverage_exclude.json`, generates `coverage/index.html`, opens it.

### Flavors & regeneration

Native flavor wiring (Android `applicationId` `com.app.<flavor>`, iOS bundle ids, Firebase
config placement) is generated by **flutter_flavorizr** from `flavorizr.yml`:

```bash
dart run flutter_flavorizr
```

Firebase per-flavor config files live under `firebase/<flavor>/`. Do **not** run
`build_runner` — the README mentions it but there is no codegen dependency and all models
are hand-written.

Naming is inconsistent across the repo: `flavorizr.yml` uses `prod`, while
`.vscode/launch.json` and `AppConfig` use `production`. `lib/flavors.dart` and
`lib/core/config/app_config.dart` each declare their **own** `Flavor` enum with different
members — keep them straight (see Configuration below).

### CI / CD

- `mobile-pr-ci.yml` is an **Azure Pipelines** definition (not GitHub Actions). On PRs to
  `develop` it runs `flutter analyze` + `flutter test --coverage`, enforces **≥60% line
  coverage** and **≤15 changed files**, and posts results as PR comments.
- `mobile_cd_android.sh` builds a release APK and uploads it via
  `firebase appdistribution:distribute`.

## Architecture

### Startup (`lib/main.dart` → `lib/app.dart` → `lib/app_router.dart`)

`main()` runs inside `runZonedGuarded`: initializes `AppConfig`, `ApiRepository.init()`,
`Firebase.initializeApp()`, wires `FlutterError.onError` / `PlatformDispatcher.onError` /
the zone handler to Crashlytics, then `runApp` with a `MultiBlocProvider`.
`App` is a `MaterialApp.router` using `GoRouterInit.router`, `flutter_screenutil` (design
size 380×844), a forced `AppTheme.lightTheme`, and disabled text scaling.

`GoRouterInit` (in `lib/app_router.dart`) is a static holder: `router`, `navigatorKey`,
`routeObserver`, plus `initialLocation` / `initialExtra` that tests overwrite before
pumping. Route names are string constants in `RouteConstants`. A
`FirebaseAnalyticsObserver` is attached unless running under `FLUTTER_TEST`.

### The BLoC layer — start here: `lib/core/base_bloc/base_bloc.dart`

Every bloc extends `BaseBloc<E, S extends ErrorState>`:

- Registers a **single** `on<E>` handler that wraps `eventHandlerMethod(event, emit)` in
  try/catch. `CustomException` (from `rq_network_flutter`) is mapped by HTTP status
  (500 / 401·403 / 422·400·404 / other) into an error state carrying `errorCode`,
  `errorMsg`, `apiMessage`, and field-level `Constraints`. Unhandled errors are logged to
  Firebase Analytics + Crashlytics (skipped when `FirebaseUtils.isFlutterTest`).
- Subclasses implement `eventHandlerMethod` (a `switch (event.runtimeType)` dispatching to
  private `_handlers`) and `getErrorState()` (returns the bloc's concrete error state).
- `ErrorState` is a plain class with **mutable** fields. States extend it and are emitted
  by cascade mutation: `emit(loginSuccess..user = user)`. Reused success-state instances
  are held as bloc fields.
- `Constraints` / `Item` (`constraints.dart`) model server validation errors;
  `Constraints.contains(path)` / `getMessage(path)` drive per-field form errors.
- `AppBlocObserver` is defined here but not registered anywhere.

Blocs live in `lib/core/bloc/<name>_bloc/` with `part` files for events/states
(`auth_bloc`, `app_bloc`, `websocket_bloc`, `items_bloc`, and a generic
`PaginationBloc<T>` under `bloc/pagination/` that takes a
`Future<PaginationResponse<T>> Function(int page, int pageSize)`). Files ending
`_example.dart` / `_usage.dart` are reference samples, not wired into the app.

`main.dart`'s root `MultiBlocProvider` provides `AuthBloc` and `AppBloc`; both are
resolved with `BlocProvider.of<...>(context)` in `InitPage` / `LoginPage`. Any new
screen that reads a bloc via `BlocProvider.of` needs that bloc registered at the root
(or a closer provider).

### Networking (`lib/core/api_repository/`, `lib/core/api_services/`)

`ApiRepository` is a static singleton. `ApiRepository.init()` configures
`rq_network_flutter`'s global `ApiEndpoint` (base URL from `AppConfig.shared.baseUrl`,
`access_token` / `refresh_token` keys, refresh-token URL + header builder + response
parser, `enableRefreshToken = true`), builds two `Dio` instances (with / without base
URL), a Hive cache store, and attaches `ApiLoggingInterceptor` (skipped under test).
`rq_network_flutter` is a **git dependency** (`gitlab.com/syedrahim/mobile_api_client`).

Service classes in `lib/core/api_services/` `extends ApiRepository` and call
`ApiRepository.apiService.post(endpoint:, data:, converter:)`. Blocs call services;
services never touch UI.

### Configuration (`lib/core/config/app_config.dart` + `lib/flavors.dart`)

- `AppConfig` reads `ENVIRONMENT`, `APP_NAME`, `SCHEME`, `SCOPE`, `HOST` from
  `String.fromEnvironment` (populated by `--dart-define-from-file`). `AppConfig.shared` is
  the singleton; `baseUrl` = `'$scheme://$scope'`. Its `Flavor` enum is
  `{ production, staging, dev, qa }`.
- `lib/flavors.dart` (`F` class, `Flavor { dev, staging, prod }`) is the
  flavorizr-generated build-flavor + display-title holder. Separate concept from
  `AppConfig`.

### Persistence

`PreferencesClient(prefs:)` wraps `SharedPreferences`, JSON-encoding the `appUser` and
`token` keys. It is constructed ad hoc wherever needed after
`SharedPreferences.getInstance()`.

### UI

Screens in `lib/views/<feature>/`; shared widgets in `lib/global_widgets/`
(`CommonButton`, `CommonTextField`, form validators in `form_helper/`, `ToastHelper`).
Theme tokens in `lib/core/theme/` (`AppTheme.lightTheme`, colors, Satoshi typography).

## Testing infrastructure (`test/test_helpers/`)

- **`pumpRoute` extension** (`pump_route.dart`) is the main harness: sets the config,
  installs `MockPathProvider` / `MockHiveCacheStore`, calls `ApiRepository.init` with a
  `DioAdapter` (`http_mock_adapter`) so all HTTP is mocked, sets
  `GoRouterInit.initialLocation`, and pumps the real `App`.
- `TestApp` wraps a single widget with `ScreenUtilInit` + `MaterialApp` for isolated
  widget tests.
- `WidgetTestHelper` provides visibility/tap assertion helpers. Widgets expose stable
  `Key('<name>_key')` values for finders.
- `FirebaseUtils.isFlutterTest` (checks `FLUTTER_TEST` env) gates every Firebase call, so
  no Firebase init is needed in tests.
- `test/test_helpers/load_test_variables.dart` is fully commented out — stale scaffolding,
  not a spec.
- CI runs `flutter test --coverage || true`, so a red suite does not fail the pipeline;
  don't assume existing tests pass.
